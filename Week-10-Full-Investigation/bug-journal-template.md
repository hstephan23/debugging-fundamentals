# Bug Journal - Full Investigation

Keep this living after the curriculum ends. The entries you make at work
are the ones that actually change your habits.

---

## Entry template

### YYYY-MM-DD — short name

- **Context / system:**
- **Symptom:**
- **Hypothesis:**
- **Reality (root cause):**
- **Key evidence / tell:**
- **Evidence source that helped most:** debugger / runtime report / trace / log / metric / test / profile / database / request history / reading / ...
- **Time to fix:**
- **What I'd change in the code to prevent this class of bug:**
- **Lesson (one sentence):**

---

## Review prompts (answer every ~10 entries)

- Which class of bug shows up the most for me?
- Which evidence source, when I reached for it, saved the most time? Which did I skip when I shouldn't have?
- Where am I slowest? (State inspection? Reproduction? Logs? Data flow? Environment? Nondeterminism?) Is there a skill to sharpen there?
- What check, warning, lint, assertion, schema, or test would have caught this earlier?
- What test, if present, would have caught it before it shipped?
