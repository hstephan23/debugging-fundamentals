# Bug Journal — Capstone

Keep this living after the curriculum ends. The entries you make at work
are the ones that actually change your habits.

---

## Entry template

### YYYY-MM-DD — short name

- **Context / system:**
- **Symptom:**
- **Hypothesis:**
- **Reality (root cause):**
- **Key evidence / tell:**
- **Tool that helped most:** GDB / Valgrind / ASan / TSan / rr / logs / strace / perf / reading / ...
- **Time to fix:**
- **What I'd change in the code to prevent this class of bug:**
- **Lesson (one sentence):**

---

## Review prompts (answer every ~10 entries)

- Which class of bug shows up the most for me?
- Which tool, when I reached for it, saved the most time? Which did I skip when I shouldn't have?
- Where am I slowest? (Memory? Concurrency? Build/env?) Is there a skill to sharpen there?
- What warning or lint would have caught this at compile time?
- What test, if present, would have caught it before it shipped?
